# Conditional Rendering, Expressions, and `&&` in React & JavaScript

## Why Can We Use Ternary in JSX But Not `if`?

### JSX Allows Expressions

Valid:

```jsx
{count}

{count + 1}

{condition ? <A /> : <B />}

{condition && <A />}
```

Reason:

* Expressions produce a value.
* JSX expects a value inside `{}`.

---

### JSX Does NOT Allow Statements

Invalid:

```jsx
{
  if(condition){
    ...
  }
}
```

```jsx
{
  for(...) {
    ...
  }
}
```

Reason:

* `if`, `for`, `while` are statements.
* Statements do not evaluate to a value.
* JSX needs a value to render.

---

# Expression vs Statement

## Expression

Produces a value.

Examples:

```js
5

2 + 3

name

count + 1

condition ? "Yes" : "No"

condition && "Hello"
```

All evaluate to a value.

---

## Statement

Performs an action.

Examples:

```js
if(condition){
  ...
}

for(...){
  ...
}

while(...){
  ...
}
```

These do not produce a value.

---

# Conditional Rendering

## Ternary Operator

```jsx
{
  showDetails
    ? <p>Hello</p>
    : null
}
```

Meaning:

```text
If showDetails is true:
    render paragraph

Else:
    render nothing
```

Returns either:

```jsx
<p>Hello</p>
```

or

```jsx
null
```

---

## Logical AND (`&&`)

```jsx
{
  showDetails &&
  <p>Hello</p>
}
```

Meaning:

```text
If showDetails is true:
    render paragraph

Else:
    render nothing
```

Returns either:

```jsx
<p>Hello</p>
```

or

```jsx
false
```

React ignores `false`, so nothing is rendered.

---

# Why Does `&&` Work?

Many people think:

```js
true && "Hello"
```

returns:

```js
true
```

It does **NOT**.

JavaScript's `&&` does not always return a boolean.

---

# Actual Rule of `&&`

For:

```js
a && b
```

JavaScript:

1. Evaluates `a`
2. If `a` is falsy → returns `a`
3. Otherwise → returns `b`

---

# Examples

## Example 1

```js
true && "Hello"
```

Result:

```js
"Hello"
```

---

## Example 2

```js
false && "Hello"
```

Result:

```js
false
```

---

## Example 3

```js
5 && 10
```

Result:

```js
10
```

---

## Example 4

```js
0 && 10
```

Result:

```js
0
```

---

## Example 5

```js
"abc" && [1,2,3]
```

Result:

```js
[1,2,3]
```

---

# Mental Model

Think:

```text
&& returns:

1. The first falsy value

OR

2. The last value if everything is truthy
```

---

## Example

```js
5 && 10 && 20
```

Result:

```js
20
```

No falsy value encountered.

---

## Example

```js
5 && 0 && 20
```

Result:

```js
0
```

First falsy value encountered.

# Why React Uses `&&`

Example:

```jsx
{
  showDetails &&
  <p>Hello</p>
}
```

### Case 1

```js
showDetails = true
```

Expression becomes:

```jsx
true && <p>Hello</p>
```

Result:

```jsx
<p>Hello</p>
```

React renders it.

---

### Case 2

```js
showDetails = false
```

Expression becomes:

```jsx
false && <p>Hello</p>
```

Result:

```js
false
```

React ignores `false`.

Nothing is rendered.

---

# Ternary vs `&&`

## Ternary

```jsx
{
  showDetails
    ? <p>Hello</p>
    : null
}
```

Returns:

```jsx
<p>Hello</p>
```

or

```jsx
null
```

---

## `&&`

```jsx
{
  showDetails &&
  <p>Hello</p>
}
```

Returns:

```jsx
<p>Hello</p>
```

or

```jsx
false
```

---

React ignores both:

```jsx
null
```

and

```jsx
false
```

Therefore both approaches produce the same visible result.

---

# When To Use Which

## Use `&&`

When there is only a "true" case.

```jsx
{
  isLoggedIn &&
  <Dashboard />
}
```

Read as:

```text
Render Dashboard if user is logged in.
```

---

## Use Ternary

When there is both a "true" and a "false" UI.

```jsx
{
  isLoggedIn
    ? <Dashboard />
    : <Login />
}
```

Read as:

```text
If logged in:
    show Dashboard

Else:
    show Login
```

---

# Show/Hide Text Pattern

State:

```jsx
const [showDetails, setShowDetails] =
  useState(false);
```

Toggle:

```jsx
onClick={() =>
  setShowDetails(prev => !prev)
}
```

Button Text:

```jsx
{
  showDetails
    ? "Hide"
    : "Show More"
}
```

Content:

```jsx
{
  showDetails &&
  <p>Extra Details</p>
}
```

Flow:

```text
Button Click
↓
Toggle Boolean State
↓
React Rerenders
↓
Button Text Changes
↓
Content Appears/Disappears
```
